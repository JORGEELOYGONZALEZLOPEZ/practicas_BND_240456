Integridad, restricciones y auditoría

  • PRIMARY KEY: identifica de forma única cada fila mediante ID en las entidades; la especificación lo indica para las tablas.
  • FOREIGN KEY: exige que cada referencia apunte a una fila existente. En el modelo, las FK relacionan módulos; tb_categories.parent_category_ID es autorreferente.
  • UNIQUE: se declara para tb_users.email, tb_roles.name, tb_companies.tax_id, tb_products.sku, tb_carts.user_ID, tb_user_profiles.user_ID, tb_employees.user_ID, tb_invoices.order_ID y tb_invoices.invoice_number.
  • CHECK: la descripción especifica tb_products.price > 0 y cantidades positivas en artículos del carrito. No se inventan otros CHECK.
  • Triggers: la especificación describe tb_logs como destino de auditoría de operaciones create/read/update/delete. No identifica nombres, eventos por tabla ni definiciones SQL de triggers; deben verificarse en el DDL antes de asegurar cobertura. La bitácora no tiene FK transaccionales.

Las claves o reglas no detalladas en el listado se marcan como no especificadas. Los tipos se presentan como tipos lógicos orientativos cuando el DDL físico no fue suministrado para este modelo.
